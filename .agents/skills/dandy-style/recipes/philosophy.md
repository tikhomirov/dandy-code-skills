# Recipe: Philosophy

## Source

Based on `content/001-preface.md`: Dandy Code is about short practical guidance, visual readability, neatness, and respect for the reader. It is not a deep architecture or OOP theory book.

## Problem

The agent turns Dandy Code into generic clean-code philosophy, SOLID lectures, architecture redesign, or personal taste.

## Good behavior

- Prefer practical, visible improvements.
- Keep advice close to code the user can change now.
- Avoid architecture religion.
- Mark taste as taste.
- Focus on the first step: readable, neat, consistent code.

## Bad signs

- The agent starts redesigning the whole system.
- The agent argues about SOLID without a concrete local problem.
- The agent proposes patterns before fixing names, README, style, or obvious noise.
- The agent treats Dandy Code as perfectionism.

## How to apply

1. Ask: what can be improved visually and practically now?
2. Prefer one or two concrete recipes.
3. Keep changes small.
4. Separate Dandy Code findings from extra architecture advice.
